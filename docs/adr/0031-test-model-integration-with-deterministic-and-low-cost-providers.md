# Test model integration with deterministic and low-cost providers

The first release defines `openai-compatible-v1` as a documented, tested subset of `POST /v1/chat/completions` covering messages, SSE streaming, function-style Tool Calls, and Tool Call result messages; the Control Plane owns all Conversation and Agent Loop state and does not depend on provider-hosted conversations or tools. Normal automated tests use a deterministic local Model Provider simulator, while explicitly enabled end-to-end contract tests may call a Platform Operator-configured, low-cost provider that supports function calling; the documentation may use Alibaba Cloud Model Studio `qwen-flash` as a mainland-China example but neither that provider nor model is a runtime dependency.

This separation keeps Sandbox and Agent Loop tests repeatable, offline, and free of model variability or accidental charges, while retaining a small real-provider test that detects compatibility drift across the complete integration path. Real-provider tests validate protocol and orchestration behavior rather than model intelligence or exact prose, remain disabled in ordinary CI, and inherit the Agent Run Tool Call and output budgets.
