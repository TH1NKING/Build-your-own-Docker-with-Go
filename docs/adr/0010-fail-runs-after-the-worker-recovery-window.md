# Fail Agent Runs after the Worker recovery window

The first release coordinates Executions with heartbeats and generation-stamped Execution Leases: after a Worker Node disconnects, its Agent Runs enter recovery and may resume only on that same Worker within a bounded window if the Sandbox still exists. After the window expires, the Run fails with `worker_lost` and only an explicit Platform Operator retry creates a new Run; the system will not add a distributed filesystem, CRIU checkpointing, cross-Worker migration, or automatic re-execution, avoiding duplicate side effects and disproportionate operational complexity for a single-Worker deployment. Persisting recoverable Workspace state at completed Execution boundaries may be added later without changing this failure contract.
