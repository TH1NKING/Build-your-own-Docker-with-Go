# Protect durable data with retention and admission controls

Conversations, Messages, bounded Execution Results, and Attachments remain durable until the Platform Operator explicitly deletes their Conversation, while unattached Run Artifacts expire seven days after their Agent Run ends, Sandbox Files disappear with their Sandbox, and provisional model-stream deltas are not retained. Configurable first-release defaults limit one Attachment to 20 MiB, extracted Run Artifacts to 100 MiB per Agent Run, and all durable ArtifactStore objects to 10 GiB per installation; reaching an object quota rejects new uploads or promotions, and reaching 80 percent Control Plane disk use rejects new Agent Runs, but neither condition silently deletes durable data or prevents inspection and explicit deletion.

Production backs up PostgreSQL daily to a separate private OSS prefix, retaining seven daily and four weekly backups, and combines application cleanup with an OSS lifecycle rule scoped narrowly to temporary Run Artifact objects. Capacity and cost alerts are enabled, keeping the 40 GiB Control Plane disk and pay-as-you-go ArtifactStore bounded without adding a storage-management service or weakening the lifetime rules in ADR-0006.
